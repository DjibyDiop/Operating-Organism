# Public Source Boundary

Operating Organism is a public-facing repository with a protected source boundary.

Copyright (c) 2026 Djiby Diop. All rights reserved.

## Public Surface

The public repository may contain architecture notes, interface contracts, selected source snapshots, build scripts, security notices, and integration documentation that Djiby Diop intentionally publishes.

Public visibility is for inspection, research, portfolio review, and collaboration discussion only. It does not grant permission to copy, reuse, redistribute, commercialize, train on, rehost, or derive competing systems from the project source.

## Private Surface

The following categories are private unless explicitly published by Djiby Diop:

- internal tools and operator workspaces
- private model assets, weights, exports, prompts, and datasets
- deployment material and machine-specific scripts
- experimental source not selected for public release
- credentials, tokens, local keys, and environment files
- private repositories linked to Operating Organism

## Repository Hygiene Rule

Do not commit private workspaces, local generated artifacts, model binaries, secrets, or host-specific files to this public repository. Keep those files in private repositories, local ignored folders, or dedicated release artifacts with explicit approval.
